# KisanFlow

KisanFlow is a mobile app that helps farmers book procurement slots at mandi (grain market) centres — check live wait times, get a recommended centre, book a slot, and track bookings. It also has an AI assistant you can type to or talk to, which can look things up, recommend a centre, and help you book — with a confirm button so nothing books without your approval.

---

## What's inside this app

- **Farmer app (React + Capacitor)** — the main app. Works fully on its own, no AI setup needed.
- **AI text/voice assistant** — an optional add-on that needs two small local servers running (explained below). Without them, the rest of the app still works normally.

---

## Tech used

- **Frontend:** React + TypeScript + Vite + Tailwind CSS
- **Mobile packaging:** Capacitor (turns the web app into an Android app)
- **Database:** Supabase (Postgres)
- **AI chat:** Google Gemini
- **AI voice:** Pipecat (Python), using Deepgram for speech-to-text and Cartesia for text-to-speech
- **AI knowledge base (RAG):** ChromaDB + FastAPI, for answering questions from uploaded documents (e.g. mandi rules, MSP rates)

## 1. Setting up the main app (required)

This is all you need to run the app itself — booking, wait times, everything except AI chat/voice.

### Requirements
- Node.js installed
- A free [Supabase](https://supabase.com) project

### Steps

1. **Clone the project and install packages**
   ```bash
   git clone <repo-url>
   cd Kisan-flow-mobile-app
   npm install
   ```

2. **Set up the database**
   - Create a new Supabase project.
   - Open the SQL editor in Supabase and run everything inside `supabase_schema.sql`.

3. **Add your environment variables**
   - Copy `.env.example` to a new file named `.env`.
   - Fill in your Supabase URL and key (found in your Supabase project settings).

4. **Run the app**
   ```bash
   npm run dev
   ```
   This opens the app in your browser for development.

5. **Build for Android** (once ready to package it)
   ```bash
   npm run build
   npx cap sync android
   npx cap open android
   ```
   This opens the project in Android Studio, where it can be built into an APK.

## 2. Setting up the AI assistant (optional)

The AI assistant has two parts. Both run locally as small Python servers. If these aren't running, the assistant button just won't respond — nothing else in the app breaks.

### A. Text + voice chat brain (Gemini)

No separate server needed for basic text chat — it calls Google's Gemini API directly from the app. You just need an API key:

- Get a Gemini API key from [Google AI Studio](https://aistudio.google.com).
- Add it to your `.env` file as `VITE_GOOGLE_GENAI_API_KEY`.

### B. Knowledge base server (for answering questions from documents)

```bash
cd src/agent/rag
pip install -r requirements.txt   # or install fastapi, uvicorn, chromadb, sentence-transformers manually
uvicorn rag_api:app --reload --port 8000
```
Leave this running in its own terminal. It serves answers from whatever documents were processed into the `vector_db` folder.

### C. Voice assistant server (Pipecat)

```bash
cd src/agent
uv run bot.py
```
(or `python bot.py` if not using `uv`)

This starts the voice server at `http://localhost:7860`. You'll need API keys in your `.env` for:
- `GOOGLE_API_KEY` (Gemini)
- `DEEPGRAM_API_KEY` (speech-to-text)
- `CARTESIA_API_KEY` (text-to-speech)
- Your Supabase URL and key (same as the main app)

Once both servers are running, open the app and tap the assistant — the mic button lets you talk, or you can type normally in the same conversation.

## How the AI booking flow works

1. You ask to book a slot (by typing or talking) — e.g. "book 50 quintals of wheat for tomorrow."
2. The AI proposes a draft booking and shows the details on screen.
3. **Nothing is booked yet.** You have to tap **Confirm Booking** for it to actually go through.
4. Once confirmed, it's saved to the database and shows up in your bookings.

This applies the same way whether you used text or voice — the AI can only ever suggest a booking, never finalize one without your tap.

## Notes for whoever builds the Android app

- You don't need Python, `venv`, or any of the AI servers to build or run the base app — those only matter if testing the AI assistant locally.
- `.env` is never included in the repo (see `.gitignore`) — you'll need your own Supabase and API keys, or ask the project owner for a shared `.env` for testing.
- The `android/` folder is regenerated by Capacitor commands — don't manually edit files inside it unless you know what you're changing.
